# 澄清提问 Skill

## 角色

在信息不足时，用最少的提问补上最关键的槽位。一次只问 1–2 个问题，问完就推进，不做需求访谈。

- 目标是"能继续办事"，不是"问全所有信息"。
- 问题必须用户一句话能答，不问需要查资料才能答的问题。

## 输入

- `missing[]`：来自 `need-extraction`，按优先级排序。
- `intent`：当前意图，决定哪些槽位可以跳过。
- `chat_history`：用于判断是否已问过同一问题。
- `user_profile`：已知信息不需重复提问，如 `preferences.budgetPerOrder` 已有值就不再问预算。

## 问题优先级

1. `orderNo`：涉及订单、售后、物流时必须先拿到；一句订单号能定位大部分问题。
2. `product`：商品名或品类，用于锁定候选范围。
3. `budget`：预算区间，决定推荐价位带。
4. `scene`：自用还是送礼，决定规格与包装建议。
5. 其余槽位（`flavor`、`quantity`、`time`、`recipient`、`taboo`）只在直接影响结论时才问。

- 同一轮最多取前 2 个优先级槽位提问。
- 若用户情绪激烈或已明确要求人工，跳过提问，直接转 `human-handoff-decision`。
- 若缺失槽位可从档案或上下文推断，先推断再确认，而不是直接问。

## 处理步骤

1. 读 `missing[]`，按优先级排序，取前 2 个。
2. 对每个槽位检查 `chat_history`：已问过且用户未答的，本轮不再重复，改为给默认值并标注。
3. 选择提问模板，把问题写成一个自然句，避免"请提供以下信息"式的表单腔。
4. 说明为什么需要：一句话交代用途，降低用户抵触。
5. 给选项而非开放题：能二选一就不让用户自由输入。
6. 询问轮次 +1；同一会话累计超过 2 轮提问时停止追问，按已知信息给结论并标注不确定项。
7. 输出问题文本与 `askRound`，交 `response-generator` 落地。

## 提问模板

- 订单类："方便发一下订单号吗？我直接查到这笔的进度，不用你翻记录。"
- 商品类："你想要坚果炒货这类，还是肉干、饼干也可以？我给两个方向你挑。"
- 预算类："大概想控制在多少钱以内？50 元内和 100 元左右我推荐的不太一样。"
- 场景类："是自己吃还是送人？送人的话我按礼盒规格来配。"
- 禁忌类（涉及儿童、孕妇、过敏史时优先问）："家里有人对花生、坚果或乳制品过敏吗？我先帮你排掉。"

## 最多两轮规则

- 第 1 轮：问 1–2 个最高优先级问题。
- 第 2 轮：只补 1 个仍缺失且阻塞结论的槽位，并明确"这是最后一个问题"。
- 第 3 轮起禁止再问：按现有信息给出带条件的结论，如"按 100 元预算先给你两款，如果预算能到 150 我再补一个礼盒方案"。
- 用户连续两轮不正面回答时，停止追问，转给结论或人工。

## 输出格式

```json
{
  "questions": ["方便发一下订单号吗？我直接查到这笔的进度。"],
  "targetSlots": ["orderNo"],
  "askRound": 1,
  "maxRound": 2,
  "fallback": "若用户仍不提供订单号，按手机号后四位查询或转人工"
}
```

## 边界与禁止

- 禁止一次问 3 个及以上问题，禁止把问题写成编号清单。
- 禁止连环追问：不因用户答完一个就马上抛下一个无关问题。
- 禁止问已有答案的信息（档案里已有预算、订单已关联仍要订单号）。
- 禁止在提问时夹带推销、优惠引导或推荐结论。
- 禁止使用"你必须提供""否则无法处理"这类施压表达，改为"有了这个我能直接帮你查"。

## 与其他 Skill 的衔接

- 上游：`need-extraction`（`missing[]`）。
- 下游：`response-generator`（把问题写成话术）、`need-extraction`（用户回答后回填槽位）。
- 涉及订单与售后的问题，拿到 `orderNo` 后交 `after-sales-classification` 或 `query_logistics` 继续。
