# 投诉分级 Skill

## 角色

按情绪强度与影响范围给投诉定级，决定响应速度与升级路径。定级只看客观信号，不因用户语气客气就降级。

- 目标：让该快的快、该升级的不滞留。
- 定级后不讨论"是否算投诉"，直接进入处置。

## 输入

- `user_utterance`：投诉原话，含负面词、威胁性表达（12315、曝光、律师、差评）。
- `sentiment`：中性 / 不满 / 激烈。
- `order`：来自 `query_orders`，含 `orderNo, status, items[], payable, afterSalesStatus`。
- `user_profile`：`level, totalOrders, totalSpend, risk(正常/关注/高风险)`。
- `history`：本会话已发生的方案与用户拒绝记录。

## 分级标准

| 级别 | 触发信号 | 首次响应 | 处置要求 |
| --- | --- | --- | --- |
| P0 | 食品安全、异物、过敏反应、身体不适；人身威胁、聚众曝光、媒体介入 | 5 分钟内 | 立即转人工，禁止自主赔付，留存全部凭证 |
| P1 | 明确投诉表达、要求退款或赔偿、提及 12315、连续两次拒绝方案、金额超过 200 元 | 15 分钟内 | 先致歉共情，给 1 个明确方案与时限，必要时转人工 |
| P2 | 单一环节不满、催问、抱怨口味或包装、无明显损失 | 30 分钟内 | Agent 自主处理，按标准流程答复 |

- 任一 P0 信号命中即为 P0，不与 P1/P2 信号做数量比较。
- `user_profile.risk = 高风险` 时在原有级别上不降级，可上调一级。

## 处理步骤

1. 扫描原话中的风险信号：食品安全词（异物、发霉、变质、吃坏、过敏）、维权词（12315、投诉、曝光、律师、法院）、情绪词（气死、恶心、骗子）。
2. 调用 `query_orders` 核实订单与金额，判断是否已有 `afterSalesStatus` 记录，避免重复赔付。
3. 按分级标准定级，写入 `level` 与命中信号 `signals[]`。
4. 按级别给出首次响应话术要素：P0 只做共情 + 转人工告知时限；P1 共情 + 方案；P2 直接解决。
5. 列出升级路径与接收方，标注需要留存的字段。
6. 输出分级结果，交 `human-handoff-decision` 判定是否转人工。

## 升级路径

- P0：本会话立即终止自动应答，转人工专席，同步工单至品控与售后负责人；食品安全类同时要求下架核查同批次。
- P1：Agent 给一次方案；用户不接受或再次表达不满，立即升级人工。
- P2：Agent 处理完毕，用户仍不满则按 P1 重判。
- 同一会话升级不超过两次，第二次升级必须转人工，不得继续由 Agent 兜。

## 必须留存的字段

`orderNo`、`userId`、`items[]`、投诉原话全文、`signals[]`、定级结果与依据、已给出的方案与用户反馈、商品批次与保质期（食品安全类必填）、照片或视频凭证、升级时间与接收坐席。

## 输出格式

```json
{
  "level": "P1",
  "signals": ["明确要求赔偿", "提及12315"],
  "sentiment": "激烈",
  "orderNo": "",
  "firstResponseMinutes": 15,
  "escalateTo": "售后主管",
  "evidenceToKeep": ["投诉原话", "订单明细", "方案与反馈"],
  "handoffRequired": true
}
```

- `level` 只能取 `P0`、`P1`、`P2`；`signals[]` 至少 1 条，用于复核定级。

## 边界与禁止

- 禁止与用户争辩事实、禁止反问"你确定是我们的问题吗"。
- 禁止引用内部规则编号、内部定级名称（P0/P1/P2 不得出现在回复里）。
- 禁止在 P0 场景下自主承诺赔付金额或"一定赔偿"。
- 禁止用"已记录，会有人联系你"作为唯一回复，必须给具体时限。
- 禁止把食品安全投诉拆成普通口味反馈处理。

## 与其他 Skill 的衔接

- 上游：`response-generator`（识别到负面情绪）、`after-sales-classification`（分类为质量问题）。
- 下游：`human-handoff-decision`（转人工判定）、`conversation-summary`（交接摘要）、`risk-check`（R6 推诿表达复核）。
