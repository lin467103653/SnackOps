# 转人工判定 Skill

## 角色

判断当前会话是否必须交给真人坐席，并给出原因、摘要与优先级。一旦判定转人工，Agent 停止应答，不再与用户继续对话。

- 判定要保守：拿不准时转，而不是硬撑。
- 输出是明确布尔值 + 可执行交接信息，不是建议。

## 输入

- `chat_history`：本次会话全部轮次，用于统计"连续未解决"轮次。
- `user_utterance`：是否明确要求人工。
- `sentiment`：中性 / 不满 / 激烈。
- `amount`：本次争议金额，取 `query_orders` 的 `payable` 或售后差额。
- `policyResult`：`after-sales-classification` 的结论，含 `withinWindow`、`policyRefs`。
- `complaintLevel`：`complaint-triage` 的 P0/P1/P2。
- `user_profile`：`risk(正常/关注/高风险)`、是否未成年人、是否特殊人群。
- `summary`：`conversation-summary` 产出的摘要。

## 触发条件清单

命中任意一条即为 `true`，命中多条时取最高优先级。

1. 用户明确要求人工：出现"转人工""找真人""叫你领导""人工客服"。
2. 情绪激烈：出现维权、曝光、辱骂、威胁、连续三轮负面表达。
3. 金额超阈值：单笔争议金额 > 200 元，或赔付金额超出 Agent 授权范围。
4. 连续两轮未解决：Agent 已给两轮方案，用户仍表示未解决或明显不满。
5. 超出政策：诉求落在政策 `exceptions[]` 内、超 `refundWindowDays`、或政策无对应条款。
6. 疑似诈骗：涉及中奖、返现、索要验证码/银行卡、要求私下转账。
7. 特殊人群：未成年人独立下单、孕妇/老人/病人涉及食品安全或身体不适。
8. 投诉定级 P0：食品安全、异物、过敏反应、人身伤害。

## 优先级映射

| 优先级 | 条件 | 响应要求 |
| --- | --- | --- |
| `紧急` | P0、食品安全、人身伤害、疑似诈骗、监管投诉 | 5 分钟内接入 |
| `高` | 金额 > 200 元、情绪激烈、超政策、连续两轮未解决 | 15 分钟内接入 |
| `普通` | 用户主动要求人工、其他兜底情形 | 30 分钟内接入 |

## 处理步骤

1. 逐条比对触发条件，记录 `triggeredBy[]`（条件编号 + 证据片段）。
2. 计算优先级，取命中条件中最高的那一档。
3. 生成 `reason`：一句话说明为什么转，不写内部编号。
4. 附上 `summary`（不超过 200 字），保证坐席无需回看对话。
5. 输出交接对象：售后坐席 / 品控 / 风控 / 客服主管。
6. 给用户一句可发送的转接告知，包含等待时长与需要补充的信息。
7. 交接完成后停止应答，不得再接话或补充营销内容。

## 输出格式

```json
{
  "handoff": true,
  "priority": "紧急",
  "triggeredBy": [{"rule": 8, "evidence": "用户称吃后肚子不舒服"}],
  "reason": "涉及食用后身体不适，属食品安全范畴",
  "summary": "≤200 字会话摘要",
  "assignTo": "品控 + 售后主管",
  "userFacing": "已为你转接专人，5 分钟内会有人联系你，先别丢弃商品和包装。",
  "stopAutoReply": true
}
```

- `handoff = false` 时只输出 `handoff`、`reason`、`nextAction`，其余字段可省略。

## 转人工后行为

- `stopAutoReply = true`：Agent 立即停止自动回复，仅保留"已在处理中，请稍等"这类状态提示。
- 不再给出新的方案、价格、优惠或政策解释，避免与坐席口径冲突。
- 用户继续追问时，统一回复等待时长，不回答具体结论。
- 交接单必须包含：会话摘要、订单号、用户原话、已给方案、用户拒绝记录、需要坐席决定的事项。

## 边界与禁止

- 禁止为了"降低转人工率"而压着不转；命中条件即转。
- 禁止承诺"很快有人联系"而不给具体分钟数。
- 禁止在转人工后继续自主赔付或承诺补偿。
- 禁止把内部编号、判定规则、优先级代码写进给用户的话术。
- 禁止在没有摘要的情况下交接，空摘要视为无效交接。

## 与其他 Skill 的衔接

- 上游：`complaint-triage`、`after-sales-classification`、`conversation-summary`、`risk-check`（R7 疑似诈骗）。
- 下游：人工坐席工单系统；转人工前最后一道为 `response-generator` + `risk-check`。
